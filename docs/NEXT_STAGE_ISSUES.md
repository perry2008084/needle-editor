# Project Needle 下一阶段 Issue 清单（2026-05）

这份文档把 `docs/NEXT_STAGE_PLAN.md` 进一步拆成可直接转成 GitHub Issues 的任务列表。

使用建议：
- 每条 Issue 单独建卡
- `P0` 优先进入最近 sprint
- 每条卡都尽量配一个最小可验证产物
- 不要把 plugin_host 线和编辑体验线同时全开，容易把自己拆成八瓣

---

## P0：编辑体验收口

### ISSUE-001 更细粒度文本同步
**优先级：P0**  
**对应主线：** 编辑体验收口

**目标**
- 减少 GUI 与 core 之间整块同步带来的状态抖动
- 让输入、撤销、切换标签后的文本状态更稳定

**建议内容**
- 梳理当前 UI -> core 同步路径
- 梳理当前 core -> UI 回写路径
- 将“整块覆盖式同步”逐步收紧到更细粒度策略
- 为常见编辑路径补回归测试

**验收标准**
- 连续输入时不出现明显光标跳动
- undo/redo 后文本与光标状态基本正确
- 切标签再切回不出现意外覆盖

**依赖**
- 无

---

### ISSUE-002 统一 cursor / selection 语义
**优先级：P0**  
**对应主线：** 编辑体验收口

**目标**
- 明确光标、选区、命令执行后的更新规则
- 避免 Find / Goto / 行操作后 selection 状态混乱

**建议内容**
- 整理单选区下的规则
- 预留多选区扩展边界
- 统一命令执行后的 selection 更新逻辑
- 为 goto_line / select_line / duplicate_line / move_lines_* 补测试

**验收标准**
- 常见命令执行后光标位置可预期
- selection 不会“乱飞”
- 后续多选区扩展不需要大返工

**依赖**
- ISSUE-001 最好先做或并行推进

---

### ISSUE-003 查找结果高亮与导航增强
**优先级：P0**  
**对应主线：** 编辑体验收口

**目标**
- 把当前“能查”升级成“查起来顺手”

**建议内容**
- 当前文件查找结果高亮
- 当前匹配项高亮与状态提示
- Next / Previous 的更清晰导航反馈
- Find 面板的交互整理

**验收标准**
- 用户能一眼看到当前匹配结果
- 连续跳转时不容易丢上下文
- Replace / Replace All 行为更可理解

**依赖**
- ISSUE-001 / ISSUE-002 会提升稳定性

## P0：配置系统补全

### ISSUE-004 用户全局 settings 文件
**优先级：P0**  
**对应主线：** 配置系统完整化

**目标**
- 从只有项目级配置，升级到用户级 + 项目级双层配置

**建议内容**

- 实现用户配置读取

- 无项目时也能应用全局配置
- 错误配置不会直接把应用搞挂

**依赖**
- 无

## P0：搜索能力服务化

### ISSUE-007 建立 crates/search 文件索引基础版
**优先级：P0**  
**对应主线：** 搜索能力服务化

**目标**
- 把搜索逻辑从 UI 层往正式模块迁移

**建议内容**
- 在 `crates/search` 建立文件索引接口
- 提供基础查询 API
- 先不追求超复杂算法，先把结构立住

**验收标准**
- `crates/search` 不再是占位 crate
- Quick Open 可逐步接入该模块
- 搜索逻辑不再主要散落在 UI 层

**依赖**
- 无

### ISSUE-008 Quick Open 改接搜索模块
**优先级：P0**  
**对应主线：** 搜索能力服务化

**目标**
- 把 Quick Open 从“UI 里自己干活”升级到“调搜索服务”

**建议内容**
- 将索引与匹配逻辑迁移到 `crates/search`
- 保留当前可用交互
- 顺手优化模糊排序基础版

**验收标准**

### ISSUE-009 Find in Project 后台任务化
**优先级：P0**  
**对应主线：** 搜索能力服务化

**目标**
- 让项目搜索不再明显阻塞 UI

**建议内容**
